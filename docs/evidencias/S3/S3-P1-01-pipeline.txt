1. Cambios
----------

doc-service:
  - Dockerfile: ENTRYPOINT -> CMD ["/usr/local/bin/api"]. Sin esto, el wrapper
    /entrypoint.sh termina en `exec "$@"` sin argumentos y el contenedor sale
    con exit 0.
  - .github/workflows/ci.yml: reescrito. Jobs lint (go vet + gofmt), unit
    (paquetes herméticos) e integration (Mongo single-node RS rs0 + Redis).
  - .github/workflows/release.yml: nuevo. Push a main y tags v*; QEMU + Buildx;
    multi-arch amd64/arm64; metadata sha/semver/latest; provenance + SBOM;
    Trivy sobre el digest.
  - gitleaks.yml: sin cambios (el escaneo de secretos ya existía).

infra:
  - compose/docker-compose.yml: doc-service usa
    image ${DOC_SERVICE_IMAGE:-ghcr.io/alejo-basile/doc-service}:${DOC_SERVICE_TAG:-latest},
    sin build:, con command ["/usr/local/bin/api"].
  - compose/docker-compose.build.yml: nuevo override de desarrollo
    (image doc-service:local + build.context).
  - compose/doc-service/entrypoint.sh: exporta los nombres que espera la app
    (MINIO_ACCESS_KEY, MINIO_SECRET_KEY, REDIS_PASSWORD); antes exportaba
    SVC_DOCSERVICE_* / REDIS_STREAMS_PASSWORD.
  - scripts/deploy-doc-service.sh: pull, up -d --no-build, espera healthy,
    exige /healthz 200 por Traefik e imprime el digest.
  - .env.example: DOC_SERVICE_IMAGE + DOC_SERVICE_TAG.

4. Hallazgos de estado local (reparados para el smoke; fuera de git)
-------------------------------------------------------------------

a) Credenciales de Mongo desincronizadas tras la rotación de S2:
   - .env tenía MONGO_INITDB_ROOT_PASSWORD / MONGO_APP_PASSWORD /
     MONGO_WORKER_PASSWORD distintos de secrets/*.txt.
   - El volumen de Mongo autenticaba root con el secreto, no con .env, y los
     usuarios de aplicación (docservice, worker) no existían.
   - Se alinearon las tres claves de .env con los secretos y se re-ejecutó
     mongo-init:
       "Usuario creado: docservice"
       "Rol documentsUpdater creado."
       "Usuario creado: worker"
       "Inicializacion de Mongo completada."
   - Verificación: ping como docservice con el secreto -> 1.

b) DNS interno: infra-redis-streams-1 había perdido el alias de servicio
   redis-streams en infra_data (el nombre de contenedor sí resolvía).
   Se recreó por Compose; aliases nuevos:
   ["infra-redis-streams-1","redis-streams"]; nslookup redis-streams -> OK.

c) Sentinel 1/2/3 siguen en Restarting: deuda de S2, fuera del alcance de
   S3-P1-01. No afecta el smoke de doc-service (conecta al primario).
