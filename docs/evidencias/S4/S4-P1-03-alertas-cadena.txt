=== Objetivo ===
Verificar que las alertas de cadena "QueueNotAdvancing" y "DLQNotEmpty" se disparan
artificialmente y pasan a estado 'firing', usando un stack aislado (compose test)
con stream de prueba separado.

=== Stack aislado ===
Archivo: infra/compose/docker-compose.test-alerts.yml
Proyecto: s4p103-test
Redes: s4p103_test_data (interna), s4p103_test_internal (interna)
Servicios:
  - redis-test:7.2 (requirepass=<REDIS_TEST_PASSWORD>; credencial efímera, generada en ejecución y nunca versionada)
  - redis-exporter-test:oliver006/redis_exporter:v1.93.0
    --check-single-streams=stream:s4p103-test,stream:s4p103-test-dlq
  - prometheus-test:prom/prometheus:v2.53.4
    config: infra/compose/prometheus/prometheus.test.yml
    rule_files: [/etc/prometheus/alert.rules.yml] (monta alert.rules.test.yml)
  - alertmanager-test:prom/alertmanager:v0.34.1

=== Reglas de alerta (infra/compose/prometheus/alert.rules.test.yml) ===
- QueueNotAdvancing: redis_stream_length{stream="stream:s4p103-test"} > 0
  and changes(redis_stream_length{stream="stream:s4p103-test"}[5m]) == 0
  for: 0m, severity: warning
- DLQNotEmpty: redis_stream_length{stream="stream:s4p103-test-dlq"} > 0
  for: 0m, severity: critical

=== Prueba integrada (scripts/test-chain-alerts.sh) ===

1. Levantar stack aislado
   docker compose -f infra/compose/docker-compose.test-alerts.yml -p s4p103-test up -d --build
   ✓ Todos los contenedores Running

2. Verificar redis-exporter (redis_up=1)
   docker run --rm --network s4p103_test_data curlimages/curl:8.7.1 \
     curl -s http://redis-exporter-test:9121/metrics | grep "redis_up 1"
   ✓ redis-exporter respondiendo (redis_up=1)

3. Test 1: QueueNotAdvancing - Agregar mensaje y esperar 5 min
  docker compose -f infra/compose/docker-compose.test-alerts.yml -p s4p103-test \
    exec -T redis-test redis-cli -a <REDIS_TEST_PASSWORD> \
    XADD stream:s4p103-test '*' payload '{"document_id":"test-queue"}'
   Resultado: 1793064122366-0 (entry ID)

   Verificar profundidad constante (XLEN) durante 5 min:
     Iteración 1: XLEN = 1
     Iteración 2: XLEN = 1
     Iteración 3: XLEN = 1
     Iteración 4: XLEN = 1
     Iteración 5: XLEN = 1

   Verificar alerta en Prometheus (después de 5 min):
   docker run --rm --network s4p103_test_internal curlimages/curl:8.7.1 \
     curl -s http://prometheus-test:9090/api/v1/alerts | \
     jq -r '.data.alerts[] | select(.labels.alertname=="QueueNotAdvancing") | .state'
   ✓ QueueNotAdvancing: FIRING

4. Test 2: DLQNotEmpty - Agregar mensaje a DLQ
  docker compose -f infra/compose/docker-compose.test-alerts.yml -p s4p103-test \
    exec -T redis-test redis-cli -a <REDIS_TEST_PASSWORD> \
    XADD stream:s4p103-test-dlq '*' payload '{"document_id":"test-dlq"}'
   Resultado: 1793064430784-0 (entry ID)

   Esperar 10s para scrape y evaluación:
   Verificar alerta en Prometheus:
   docker run --rm --network s4p103_test_internal curlimages/curl:8.7.1 \
     curl -s http://prometheus-test:9090/api/v1/alerts | \
     jq -r '.data.alerts[] | select(.labels.alertname=="DLQNotEmpty") | .state'
   ✓ DLQNotEmpty: FIRING

5. Limpieza de mensajes de prueba
   XDEL stream:s4p103-test 0
   XDEL stream:s4p103-test-dlq 0
   Ambos comandos devolvieron 0 (mensaje eliminado)

6. Verificar resolución (las alertas siguen firing hasta que Prometheus reevalúa
   y ve depth=0 / DLQ vacía; el stack se detiene antes de la resolución natural)
   QueueNotAdvancing state: firing
   DLQNotEmpty state: firing

7. Detener stack aislado
   docker compose -f infra/compose/docker-compose.test-alerts.yml -p s4p103-test down -v
   ✓ Contenedores, volúmenes y redes removidos

=== Nota de seguridad ===
- Las credenciales de este stack aislado se generan en tiempo de ejecución (REDIS_TEST_PASSWORD,
  girado por ejecución) y se inyectan vía REDISCLI_AUTH como variable de entorno, NUNCA por argv
  y NUNCA versionadas. Los valores reales de los comandos históricos de esta evidencia están
  redactados como <REDIS_TEST_PASSWORD>; el script committed (scripts/test-chain-alerts.sh) ya
  no contiene contraseñas literales en ninguna parte del árbol.

=== Limitaciones ===
- Prometheus test usa scrape_interval: 5s; la alerta DLQNotEmpty tarda ~10s en disparar (1-2 scrapes + evaluación)
- QueueNotAdvancing requiere 5 min reales de profundidad constante (changes()[5m] == 0)
- La resolución de alertas no se probó completamente porque el stack se detiene; en producción, QueueNotAdvancing se resuelve cuando la cola avanza (changes > 0) y DLQNotEmpty cuando se vacía (XDEL o replay)
