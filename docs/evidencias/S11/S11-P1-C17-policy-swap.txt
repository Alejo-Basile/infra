== 4. Swap en caliente (sin reinicio) ==
Politica vigente al inicio: POST /api/v2/documents=5:10 (limit de ruta 10).

$ consul kv put config/rate-limiter/sensitive_routes "POST /api/v2/documents=1:1"
Success! Data written to: config/rate-limiter/sensitive_routes

Probe contra /check (ruta sensible, rate global 100 para aislar la ruta):
  request 1 (IP 198.51.100.99): {"allowed":true,"remaining":0}
  request 2 (misma IP):         wget: server returned error: HTTP/1.1 429 Too Many Requests

La ruta paso de 10 a 1 sin reiniciar: el puntero atomico se publico por el
watcher KV y handleCheck lo leyo en el siguiente request.

Restauracion del valor original:
$ consul kv put config/rate-limiter/sensitive_routes "POST /api/v2/documents=5:10"
Probe posterior: {"allowed":true,"remaining":9}

== 5. Politica invalida: descarte total, valor anterior vigente ==
$ consul kv put config/rate-limiter/sensitive_routes "POST /api/v2/documents=abc"

Log del contenedor (sin token ni valores sensibles):
  configkv: politica invalida, se conserva la anterior: rutas sensibles: limite invalido "abc": se esperaba rate:burst
  configkv: apply error: rutas sensibles: limite invalido "abc": se esperaba rate:burst

/check siguio aplicando la politica anterior (5:10) hasta restaurar la clave.

webhook_token y webhook_path nunca provienen de KV: se conservan del valor
previo y del entorno (RL_WEBHOOK_TOKEN/RL_WEBHOOK_TOKEN_FILE).

== 6. Observaciones fuera del alcance de C17 (defectos preexistentes de C12) ==
1. La cache last-known-good no se puede escribir en el volumen:
   configkv: no se pudo guardar la cache: open /var/lib/ratelimitd/config-cache.json.tmp: permission denied
   El volumen nombrado queda con dueno root y el contenedor corre como 10001.
2. El cliente KV corta la blocking query a los 10 s (http.Client.Timeout=10s)
   mientras usa wait=5m, asi que cada ciclo largo termina en:
   configkv: error de Consul: ... wait=5m0s ... context deadline exceeded (status 0)
   y reintenta con backoff. El swap funciona porque el watcher reintenta, pero
   el long-poll no se sostiene.

Ambos son del cliente KV (C12) y quedan registrados como seguimiento, no se
corrigieron en C17.
