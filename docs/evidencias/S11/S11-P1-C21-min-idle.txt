S11-P1-C21 — extraction-worker: min_idle_ms restart-only
Date: 2026-11-18

Scope
-----
This task makes a change to min_idle_ms published through Consul KV persist and be logged
once, while the effective value used by the XAUTOCLAIM loop stays the startup value until
restart. Hot changes to job_timeout_seconds never recalculate min_idle_ms.

Behavior verified
-----------------
- Effective min_idle_ms equals the startup value (WORKER_MIN_IDLE_MS, default 601000 =
  300*2000+1000 with job_timeout=300s).
- A valid new min_idle_ms arriving from Consul KV is persisted by the existing configkv
  last-known-good cache and recorded as pending; the effective value used by XAUTOCLAIM
  stays the startup value.
- min_idle_change_requires_restart is emitted exactly once per distinct requested value.
  Re-publishing the same value does not log again; a different value logs again once;
  reverting to the effective value clears the pending state without logging.
- WorkerKvOverlay::apply never writes cfg.min_idle_ms.
- Changing job_timeout_seconds in KV does not recalculate min_idle_ms.
- After restart, a new WORKER_MIN_IDLE_MS env value or cache value becomes effective.
- Startup warns (never aborts) when min_idle_ms < 2 * job_timeout.
