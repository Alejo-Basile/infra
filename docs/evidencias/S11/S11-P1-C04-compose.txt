Deviations from task-4.md (all deliberate, observed):
- Secrets/certs are generated in C04 via consul-dev-secrets.sh instead of bare placeholders:
  hardcoded placeholder strings prevent Consul from starting (gossip encrypt and TLS).
  C05 rotates/hardens gossip + TLS; C06 replaces the single management token with per-service ACL tokens.
- TLS uses Consul's top-level keys (ca_file/cert_file/key_file/verify_server_hostname/
  verify_outgoing/verify_incoming), not a `tls_config` block; the block form is not accepted
  by Consul 1.22 agent config.
- Config files are mounted individually read-only, never the whole /consul/config directory:
  the image entrypoint chowns that directory and a read-only dir mount aborts startup
  ("chown: /consul/config: Read-only file system").
- The agent uses the same server cert/key (SANs include consul, consul-agent,
  server.dc1.consul, localhost, 127.0.0.1) because its HTTPS listener needs cert_file/key_file.
- Gossip key and the dev management token live in the generated, gitignored
  dev-*.local.hcl files because `encrypt` is a config-only field with no file/secret support.
- An extra named volume `consul-agent-data` is mounted at /consul/data for the client agent
  (read-only rootfs needs a writable state dir; the image path lets the entrypoint chown it).

Notes:
- Dev-generated cert/key files under infra/secrets/ are created by `docker run` (root-owned,
  0644) so the container's non-root `consul` user can read them. C05 owns rotation.
- No host ports for 8500/8501. UI exposure is C09.
