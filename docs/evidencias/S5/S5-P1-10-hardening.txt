Fecha: 2026-11-10

Alcance: cierre parcial. Se aplicaron y desplegaron hardening de filesystem/usuarios/límites/digests en el perfil full + sentinel. Persisten CRITICAL corregibles en varias imágenes upstream. No se modificaron Dockerfiles ni servicios de negocio. Las salidas de Compose se validaron con `config -q` para no mostrar variables interpoladas.

## Trivy local

`docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:0.69.3 image --scanners vuln --severity CRITICAL --exit-code 1 --skip-version-check doc-service:local`

`docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy:0.69.3 image --scanners vuln --severity CRITICAL --exit-code 1 --skip-version-check extraction-worker:t10-sentinel`

La primera etapa no tuvo inventario completo de digests ni servicios upstream hardenizados; su cierre/resultado final queda registrado abajo tras las pruebas de staging.

## GREEN final — hardening desplegado

Comando de despliegue (se pasaron los digests de los artefactos locales conocidos por variables de comando, sin mostrar ni modificar `infra/.env`):
`DOC_SERVICE_DIGEST=sha256:aeb1cdcff2374e4a0a7c37006fef22476b17527b61eb2d5a3d2b13a79dee1e48 EXTRACTION_WORKER_DIGEST=sha256:006775524bd4cc8eca24e95cb7136485d5d79e0b8f230a60fd5a662fa119fb7b MONOLITO_DIGEST=sha256:0439e6a932d8ff40e5401bd574baa7d392f8ba35cd623e4ee34aec1f067442ef docker compose --env-file infra/.env -f infra/compose/docker-compose.yml -f infra/compose/docker-compose.sentinel-worker.yml --profile full --profile sentinel up -d --no-build`

Resultado: exit 0. El primer intento falló porque la sintaxis YAML inline dividió opciones `tmpfs` en mounts separados (`invalid mount path: 'nosuid'`); se corrigió citando cada valor. El siguiente intento detectó AOF Redis preexistente root-owned: Redis UID 999 no podía abrir `appendonly.aof.9.incr.aof`. Se verificó solo metadata de propietario y se cambió el owner de `/data/appendonlydir` a 999:999 en los tres volúmenes Streams; datos y archivos no se borraron. MinIO client falló inicialmente con rootfs RO porque `mc` intentaba escribir en `/.mc`; `HOME=/tmp` corrigió la ruta. Una reejecución de `minio-notify-init` tuvo un fallo DNS transitorio, registrado en su log filtrado; `up --force-recreate minio-notify-init` reintentó sin cambiar datos y terminó exit 0.

`docker ps --format '{{.Names}} {{.Status}}` final: Sentinel-1/2/3, monolito, doc-service, extraction-worker, Redis Streams + réplicas, Traefik, Mongo, Redis rate-limit, Alertmanager y MinIO aparecen `healthy`. Redis exporter, Grafana, Prometheus y Loki están `Up` y no tienen healthcheck declarado. `mongo-init`, `minio-init`, `minio-notify-init` terminaron exit 0 (jobs one-shot esperados). No se levantó el perfil chaos de Pumba.

Inspección filtrada final: todos los contenedores creados del perfil full/sentinel usan UID numérico != 0 y `ReadonlyRootfs=true`; todos tienen `cap_drop=[ALL]` y `no-new-privileges:true`. Traefik añade solo `NET_BIND_SERVICE` para :80/:443 y grupo de socket 969 para leer Docker socket. Servicios de datos añaden SETUID/SETGID/CHOWN/DAC_OVERRIDE por el entrypoint oficial; Redis Streams necesitó corregir owner del AOF antes de poder correr no-root. Los one-shot MinIO corren UID 1001, rootfs RO y `/tmp` writable.

## Intento de corrección de CVE-2023-45853 en worker

Comando:
`docker manifest inspect --verbose debian:trixie-slim | jq -r '.[0].Descriptor.digest'`

Resultado: `sha256:7378260c0a098d27ac206225db5e7d92b8c7c84ea7afccc86eeb513756bbd392`.

Comando:
`docker run --rm --entrypoint /bin/sh aquasec/trivy:0.69.3 -c 'trivy image --image-src remote --scanners vuln --severity CRITICAL --format table --report summary debian:trixie-slim@sha256:7378260c0a098d27ac206225db5e7d92b8c7c84ea7afccc86eeb513756bbd392'`

Resultado: Debian 13.7 base con 0 CRITICAL. Se aplicó el cambio a `extraction-worker/Dockerfile`, manteniendo `USER 10001:10001` y fijando el digest de runtime.

Comando:
`docker build --pull --tag extraction-worker:t5-hardening --file Dockerfile .` (workdir `extraction-worker`)

Resultado: build completado; ID `sha256:c07d2e9ed2b21076c6eada2b842ed6c72502a11b4034709c53b413c0dfd66acd`, usuario de imagen `10001:10001`.

Comando:
`docker run --rm -v /var/run/docker.sock:/var/run/docker.sock --entrypoint /bin/sh aquasec/trivy:0.69.3 -c 'trivy image --scanners vuln --severity CRITICAL --exit-code 1 --format table --report summary extraction-worker:t5-hardening'`

Resultado: Debian 13.7; 0 CRITICAL; exit 0. No se requiere allowlist ni `ignore-unfixed` para el worker actualizado. Los gates CI quedaron sin excepciones y con `exit-code: 1` para CRITICAL.

Comando de redeploy final:
`DOC_SERVICE_DIGEST=sha256:aeb1cdcff2374e4a0a7c37006fef22476b17527b61eb2d5a3d2b13a79dee1e48 EXTRACTION_WORKER_TAG=t5-hardening EXTRACTION_WORKER_DIGEST=sha256:c07d2e9ed2b21076c6eada2b842ed6c72502a11b4034709c53b413c0dfd66acd docker compose --env-file infra/.env -f infra/compose/docker-compose.yml -f infra/compose/docker-compose.sentinel-worker.yml --profile full --profile sentinel up -d --no-build`

Resultado: exit 0; `infra-extraction-worker-1` quedó `healthy` usando `extraction-worker:t5-hardening@sha256:c07d2e9ed2b21076c6eada2b842ed6c72502a11b4034709c53b413c0dfd66acd`. El resultado histórico Debian 12/CVE-2023-45853 permanece como RED, no como hallazgo actual del worker.
