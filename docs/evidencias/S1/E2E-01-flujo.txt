> Evidencia real de `scripts/e2e-01.sh` contra el stack `full`, con
> CI-A/CI-B/CI-C/CI-D aterrizados (2026-10-07).

Entorno: stack `--profile full` (`infra-mongo-1`, `infra-redis-streams-1`,
`infra-minio-1`, `infra-traefik-1`, `infra-doc-service-1`), hosts `api.localhost`
y `s3.localhost` con mkcert (ADR-0016).

## Notas de implementacion (hallazgos corregidos durante la corrida)

1. PresignPost: la firma de la POST policy SigV4 NO depende del Host header
   (se firma el documento, no el request). Se firma con el cliente interno
   `minio:9000` y la URL resultante se re-escibe al host publico
   `s3.localhost:8543`. Evita el round-trip DNS a `s3.localhost` desde el
   contenedor (que no resuelve) y mantiene la firma valida.
2. La policy `docservice-rw` de MinIO le faltaba `s3:PutObject` en `raw-pdfs/*`:
   sin ese permiso MinIO responde `AccessDenied` a la subida prefirmada (la URL
   se genera bien, pero el PUT se rechaza). Se corrigio en
   `compose/minio/init-buckets.sh` y se re-aplico la policy en vivo.
3. webhook target: se declaro via `MINIO_NOTIFY_WEBHOOK_*` en el servicio `minio`
   del compose, de modo que el target existe desde el arranque y NO dependa de
   `mc admin service restart` (que sin TTY no aplica la config). El job
   `minio-notify-init` ahora confirma el target activo y solo re-suscribe.

## DoD

- `PENDING_UPLOAD -> UPLOADED` SOLO tras existir el objeto en MinIO (webhook at-least-once).
- La URL prefirmada se firma con el host publico `s3.localhost:<puerto>` (SigV4).
- `XADD` + `WAIT`: el relay publica el trabajo; `XLEN` aumenta exactamente una vez.
- Webhook repetido: `XLEN` estable (deduplicacion por transicion condicional).
