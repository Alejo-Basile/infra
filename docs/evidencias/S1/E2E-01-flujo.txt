# E2E-01 — Flujo de subida prefirmada, pendiente -> UPLOADED (PENDIENTE)

> Plantilla de evidencia. Rellenar con la salida real de `scripts/e2e-01.sh`
> una vez aterricen CI-A/CI-B/CI-C/CI-D (ver mas abajo) y el stack `full` arranque.

Entorno: stack `--profile full` (`infra-mongo-1`, `infra-redis-streams-1`,
`infra-minio-1`, `infra-traefik-1`, `infra-doc-service-1`), hosts `api.localhost`
y `s3.localhost` con mkcert (ADR-0016).

## Comando

```bash
scripts/bootstrap.sh
docker compose -f compose/docker-compose.yml --profile full up -d --build
scripts/e2e-01.sh
```

```

== 1. POST .../api/v2/documents ==
  [OK]   document_id = idempotency_key (...)

  [OK]   upload_url apunta a s3.localhost

  [OK]   Mongo status = PENDING_UPLOAD

  [OK]   Mongo status = UPLOADED

== 7. Idempotencia: repetir POST con la misma clave ==

== 8. Deduplicacion: re-subir el mismo objeto ==
  [OK]   webhook repetido NO genero trabajo nuevo (XLEN estable)
E2E-01 OK — flujo de subida prefirmada verificado de punta a punta.
```

## DoD

- `PENDING_UPLOAD -> UPLOADED` SOLO tras existir el objeto en MinIO (webhook at-least-once).
- La URL prefirmada se firma con el host publico `s3.localhost:<puerto>` (SigV4).
- `XADD` + `WAIT`: el relay publica el trabajo; `XLEN` aumenta exactamente una vez.
- Webhook repetido: `XLEN` estable (deduplicacion por transicion condicional).
