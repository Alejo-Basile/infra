# ADR-0016 — Hostname público dedicado para MinIO (S3)

- **Estado:** Aceptado
- **Fecha:** Semana 0 (S0-P1-07)
- **Contexto:** SPEC.md v2.1 §2, §5.1, §9 · plan-P1.md (S0-P1-07, S1-P1-16)

## Contexto

La subida de PDFs se hace con **URL prefirmada de MinIO (POST con política)** que el
Document Service emite y el cliente usa directamente contra el servidor de objetos.
La firma **SigV4 incluye el *host*** dentro del *canonical request*: las mismas claves
y cabeceras producen firmas distintas para `api.dominio` y para `s3.dominio`. Si el host
con el que se firma no coincide **exactamente** con el host al que el cliente golpea, la
verificación falla con `SignatureDoesNotMatch` — un 403 con la API perfectamente sana, de
lo más difícil de diagnosticar en producción. En local nadie lo ve porque todos firman
contra `minio:9000`.

## Opciones consideradas

1. **Mismo host que la API** (`api.dominio/minio`) — rechazada: mezcla políticas del
   gateway (buffering, rate limit) con el tráfico de datos y no desacopla la firma.
2. **Host dedicado para S3** (`s3.dominio`) — **elegida**: separa superficie, permite
   políticas distintas por router y hace explícita la dependencia SigV4↔host.
3. **Path-style** (`dominio/s3`) — rechazada: no resuelve el problema de firma y complica
   la configuración de Traefik.

## Decisión

- **Producción:** el servidor de objetos se expone en **`s3.<dominio>`** (distinto de
  `api.<dominio>`), con DNS propio y certificado ACME de Let's Encrypt (staging primero).
- **Entorno local / académico (este proyecto):** no hay dominio real ni despliegue remoto.
  Se utiliza **`s3.localhost`** (y `api.localhost` para la API), con TLS local emitido por
  **mkcert** (`scripts/gen-certs.sh`). `*.localhost` resuelve a `127.0.0.1` sin tocar DNS
  del sistema en la mayoría de entornos; si no, agregar a `/etc/hosts`.
- El **valor** que usa el doc-service para firmar sale de la variable de entorno
  **`MINIO_PUBLIC_ENDPOINT`** — nunca un literal en código.

## Consecuencias

- La consola de administración de MinIO (`:9001`) **no** se expone bajo ningún hostname;
  solo el puerto S3 (`:9000`) tiene router en Traefik.
- Para demostrar la dependencia host↔firma en desarrollo: cambiar
  `MINIO_PUBLIC_ENDPOINT` a `http://minio:9000` y observar que **todas** las subidas
  fallan con `SignatureDoesNotMatch` aunque MinIO esté sano.
- Migrar a producción solo requiere cambiar DNS + ACME y el valor de
  `MINIO_PUBLIC_ENDPOINT=https://s3.<dominio>`; no hay stubs que “romper” después.

## Verificación

1. `https://s3.localhost/minio/health/live` responde con cert válido (mkcert).
2. La consola `:9001` no responde desde el entrypoint público.
3. Una subida prefirmada firmada contra `s3.localhost` funciona; firmada contra otro
   host, falla con `SignatureDoesNotMatch`.
